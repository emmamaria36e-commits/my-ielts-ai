# Backlog

> Backlog 不记录已经完成的工作，只记录经过思考后决定暂缓处理的优化事项，以及未来值得实现的想法。
>
> **与其它文档的区别：**
> - `CHANGELOG.md` — 已经完成的改动（过去）
> - `ROADMAP.md` — 各版本计划（未来的大版本）
> - `BACKLOG.md`（本文件）— 碎片化的待办、优化点、技术债（未来待办）

## 使用说明

- 每一条记录的核心是 **Reason**：写清楚为什么现在不做。未来回顾时，这个决策理由比事项本身更有价值。
- 发现一个值得记录的事项时，在对应分类表格中新增一行。
- 当某个事项被完成或正式纳入某个版本计划时，将其从 Backlog 中移除，归档至 `CHANGELOG.md` 或 `ROADMAP.md`。
- 不要在此文件记录已上线的内容。

**字段说明：**
- **#** — 自增序号，方便在讨论中引用（如 "Backlog #12"）
- **Title** — 一句话描述待办事项
- **Reason** — ★ 最重要的字段。写清楚「为什么现在不做」以及当时是怎么考虑的。未来回顾时，这个决策理由比事项本身更有价值
- **Priority** — `High` / `Medium` / `Low`
- **Status** — `Todo`（待处理）/ `Deferred`（明确决定现在不做）
- **Target Version** — 建议在哪个版本处理（如 `v0.3`、`v1.0`、`Later`）
